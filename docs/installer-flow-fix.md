# 合集安装队列与进程跟踪

更新日期：2026-11-10；对应 v1.2.5。

## 运行与目录

制作工具与生成的合集均内置 .NET 9，模板为 Windows x64 单文件，标识为 `1.2.5+selfcontained-demand-flow`。生成器会拒绝旧模板。加载已有配置后需要重新生成合集，旧合集不会自动更新。

合集统一使用安装包自己的默认目录，不传入配置中保存的 D 盘等自定义路径；与旧目录绑定的文件检测也不用于默认位置。原配置保留供制作工具直接安装使用。没有适用检测规则时，根据进程结束及返回码记录结果；独立文件、版本、MSI 产品码仅在明确配置后复核，失败最多重试约 10 秒。

## 等待和取消

- EXE 和 MSI 客户端先挂起，建立跟踪后再运行。
- Win8 及以上优先使用 Job Object；交互 EXE 允许显式 breakaway，避免部分自解压外壳启动内部程序时因进程组限制出现拒绝访问。
- Win7 不支持嵌套 Job，直接使用父子关系快照和持有的进程句柄跟踪；其他系统创建或加入 Job 失败时也自动切换，并在日志记录原始系统错误。
- 交互外壳运行时和父子跟踪模式定期读取进程的 PID、父 PID 关系；只为本次后代保留句柄及创建时间。合集启动阶段不做这项快照查询。
- 主进程退出后，继续等待资源目录、系统临时目录或 Windows 目录内的已跟踪子进程。这些目录外的程序保留运行并继续队列；系统 conhost.exe 不单独阻塞队列。
- 正常完成移除 Job 的关闭终止保护，避免误杀安装后启动的软件。取消终止受控 Job 和已跟踪的独立子进程，确认后停止后续队列。
- 日志区分等待主进程、主进程退出及返回码、仍等待的子进程 PID 和路径。异常返回码仍报告失败，不将绿色程序返回的非零值一律视为成功。

## 取舍与边界

内置运行时无需为合集另装 Framework 或 .NET，但相比 v1.2.4 的 Framework 模板，模板体积和首次启动耗时可能增加。第三方安装软件自己的运行条件不受影响。.NET 9 官方不支持 Win7；用户测试能运行不构成新的系统兼容保证。

父子快照可能漏掉采样间隔内已退出的中间程序；无 Job 时，合集异常结束无法依靠系统自动终止所有后代。MSI 服务、服务另行启动的任务、从特殊目录执行的安装程序仍需实机核对；无法确认结果时保留资源和日志。强制取消可能留下未完成的安装。

机制参考：[Microsoft Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)。

## 验证范围

仅进行 Release 编译和与改动相关的无害进程替身、目录与队列、模板生成、实际导出 EXE 启动检查；不运行默认完整回归或真实第三方安装器。Win7 跟踪分支在 Win11 强制执行同一分支检查，仍需 Win7 实机验证。

按用户要求，正式发布跳过发布包 SHA-256 验证和上传后重复下载验证，不附带校验和文件。应用在提取自身资源时的原有完整性检查保留。
